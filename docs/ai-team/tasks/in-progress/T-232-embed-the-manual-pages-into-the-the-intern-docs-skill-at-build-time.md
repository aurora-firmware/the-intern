## Description

Make the `bob` build embed the user-manual pages as the `the-intern-docs`
skill's reference pages, and commit the regenerated pi target for that skill
(CR-016 item 3; S-011 v0.3 Component 2; S-012 v0.4 Principles, "Embedded
pi-package assets", Phase 5; S-007 v0.2; ADR-017 §2).

Run `package-pi-skills.sh` and commit `.pi/skills/the-intern-docs/SKILL.md`
(T-231 registered the skill but deliberately did not commit it).

`the-intern/service/crates/bob/build.rs` embeds every file under
`the-intern/bob-skills/.pi/skills` into a generated asset table
(`embedded_pi_skill_assets()` in `src/init_assets.rs`). Extend it so the
embedded set also contains each page the docs SKILL.md index names, at the
manual's own layout: `the-intern/docs/src/<dir>/index.md` →
`the-intern-docs/references/<dir>/index.md` — i.e. `references/quickstart/index.md`, `references/end-user-guide/index.md`,
  `references/operator-guide/index.md`, `references/architecture-overview/index.md`,
  `references/extension-author-guide/index.md`.
The required page set is NOT found by scanning `docs/src`: take it from the
`references/...` paths named in the docs SKILL.md (or a fixed list matching
it), so a removed or renamed manual page fails the build instead of silently
not being embedded. `SUMMARY.md` and the CLI-reference stub are never
copied, and no copied page may be named `SKILL.md`.

Constraints (binding): the copy is never written into a tracked directory
(read the manual directly in `build.rs`, or write only under `OUT_DIR`); emit
`cargo:rerun-if-changed` for the manual pages; a clean `cargo build -p bob`
embeds the pages or panics naming the missing source path — never embeds the
docs SKILL.md without them. This is a markdown copy, not a docs build.

Update `init_assets.rs` tests: expected path list and the root set (five
roots); byte comparison of each docs page against `the-intern/docs/src`
(drift test); and a test that every `references/` path the embedded docs
SKILL.md names is embedded and every embedded docs page is named in it.

AC-1: The system shall embed `the-intern-docs/references/<dir>/index.md` for
      each page the docs SKILL.md index names, byte-identical to
      `the-intern/docs/src/<dir>/index.md`, plus the committed generated
      `.pi/skills/the-intern-docs/SKILL.md`.
AC-2: The system shall never embed `SUMMARY.md`, the CLI-reference stub, or any
      copied page named `SKILL.md`, and shall never write the copy into a
      tracked directory.
AC-3: IF a page the docs SKILL.md index names is missing from
      `the-intern/docs/src` at build time THEN THE SYSTEM SHALL fail the
      build with an error naming the missing source path.
AC-4: WHEN a manual page changes THE SYSTEM SHALL rebuild `bob` on the next
      `cargo build`.
AC-5: IF an embedded docs page differs from its manual source, or the index
      and the embedded pages disagree, THEN the `init_assets` tests shall
      fail.

## Dependencies

- `T-231` — canonical `the-intern-docs/SKILL.md` (page paths) and its packaging entry

## Files to Touch

- `the-intern/bob-skills/.pi/skills/the-intern-docs/SKILL.md` — regenerated by `package-pi-skills.sh` (do not hand-edit)
- `the-intern/service/crates/bob/build.rs` — embed the indexed manual pages under `the-intern-docs/references/`
- `the-intern/service/crates/bob/src/init_assets.rs` — path list, root set, drift and index/embedded agreement tests

## Verification

```bash
bash the-intern/bob-skills/package-pi-skills.sh
git diff --exit-code the-intern/bob-skills/.pi/skills   # generated tree committed and clean
cd the-intern/service
cargo build -p bob
cargo test -p bob init_assets
cd ../.. && test -z "$(git status --porcelain the-intern/bob-skills the-intern/docs/src)"  # nothing written into tracked dirs
```
