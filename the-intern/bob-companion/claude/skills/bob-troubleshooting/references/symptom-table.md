# bob symptom → cause → fix table

| Symptom / exact message | Likely cause | Fix |
|---|---|---|
| `bob chat`: `"bob service is not running — cannot reach admin socket at <path>"` | Admin socket unreachable from this client shell | Confirm `bob serve` is up; confirm both shells resolve the same `BOB_ADMIN_SOCK_PATH` (prefer `./scripts/bob-dev.sh` for the client) |
| Any other subcommand: `"missing admin socket at <path>"` | Same as above (`ServiceError::ServiceDown` remapped by the CLI) | Same as above |
| `WARN` log + `duplicate_extension_connection` audit event; tool calls blocked even though policy should allow them | A second, still-live connection registered the same session id — most commonly a stale `bob.ts` entry still in `~/.pi/agent/settings.json`'s `packages` list, loaded alongside the current instance; can also be another live connection left over from an earlier process | Remove the stale entry from `packages` if present — bob does not manage that file. Otherwise, confirm which `pi` process is stale (bob only logs an internal `connection_id`, not an OS process id) before terminating it |
| Bob refuses to spawn any `pi` process; log/error mentions the extension file does not exist at the resolved path | `bob.ts` not installed at the expected XDG data path, and `extension_path`/`BOB_EXTENSION_PATH` not set to point at it | Install `the-intern/pi-extension/bob.ts` at `~/.local/share/bob/extensions/bob.ts` (Linux) or set `extension_path` in `config.toml` / `BOB_EXTENSION_PATH` |
| Extension emits no events, or every `tool_call` is denied with no visible reason | `BOB_SESSION_ID` or `BOB_EXTENSION_SOCK_PATH` missing on the pi child process's env (extension warns once, then no-ops for the session — it does not crash pi) | `cat /proc/<pi-pid>/environ | tr '\0' '\n' | grep -E '^BOB_'` to confirm both are set; if missing, check how the pi child was spawned |
| `admin.sock` / `extension.sock` left on disk after a restart, new `bob serve` won't bind | Previous process was killed with `SIGKILL` before the 6-phase graceful shutdown could clean up | `rm -f "$BOB_ADMIN_SOCK_PATH" "$BOB_EXTENSION_SOCK_PATH"` before restarting; prefer `SIGTERM`/Ctrl-C to stop bob in the first place |
| A scheduled job silently never fires, with no error | Bob was stopped when the cron tick was due — missed ticks are **not** replayed on restart (this is deliberate) | Not a bug; if the tick mattered, re-add/re-trigger manually. For a per-entry `cwd` that doesn't exist at fire time, or a `--file` prompt that's missing/blank at fire time, expect a warning + monitoring failure record and the *next* tick to still fire normally |
| `npm test` in `the-intern/pi-extension` fails with `INCOMPATIBLE pi-agent version detected. Installed: <x> Supported: 0.75.3` | Installed `@earendil-works/pi-coding-agent` doesn't match the pinned extension-API version | Run the exact `npm install` command the test failure prints; do not bump the pin without updating the root `README.md` compatibility section |
| Unix-domain-socket / peer-credential test fails with `Operation not permitted` | Restrictive sandbox blocking UDS operations (per `CLAUDE.md` note) | Re-run in a normal local dev shell, not a locked-down CI/sandbox environment; this is an environment limitation, not a regression |
| `bob policy reload` reports a validation error | New ruleset failed validation | Old snapshot stays active automatically (safe failure) — fix the ruleset and reload again; no service restart needed |
| `bob schedule add` fails locally before contacting the service | Passed both `--prompt` and `--file` (or neither), or gave a relative `--cwd` | Pass exactly one of `--prompt`/`--file`; make `--cwd` absolute |
| `bob audit tail --filter <value>` rejected immediately | `<value>` isn't one of `events`, `reports`, `verdicts` | Fix the spelling/value — clap validates before any connection attempt |
| `WARN` at `bob serve` startup: `"pi_agent_model is not set; pi will choose the model from its own saved settings, which can change or fall back to a different model without notice; set pi_agent_model in the service configuration to pin it"` | `pi_agent_model` left unset in `config.toml` | Set `pi_agent_model` in `config.toml` (see `bob-setup`) and restart `bob serve` |
| Service log carries a pool worker's forwarded stderr line: `Error: Model "<value>" not found. Use --list-models to see available models.` | `pi_agent_model` set to a value the installed `pi` doesn't recognize — bob does not validate the value before spawning | Confirm the exact value with `pi --list-models <search>` (exact `<provider>/<model-id>` form), fix `pi_agent_model`, restart `bob serve` |
| A scheduled job fires on schedule but leaves no trace — no marker file/side effect, and `bob audit tail` (with or without `--filter`) shows nothing for that fire | The fire hit a pool worker already dead from an invalid `pi_agent_model` (previous row) — delivery failure this early writes no `verdict`, `event`, or `report` of any kind | Check the service log for the `Model "<value>" not found` line, fix `pi_agent_model`, restart `bob serve` |
| `bob serve` fails to start; config-load error: `"pi_agent_args must not select a model (--model found); set the model with pi_agent_model instead"` (flag name varies) | `pi_agent_args` contains a `--model`, `--models`, or `--provider` entry | Move the value to `pi_agent_model`; remove the flag — and its value, if it was a separate argument — from `pi_agent_args` |
